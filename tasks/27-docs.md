## เนื้อหาที่ต้องมี
### `README.md`
1. KaraDuck คืออะไร (สองถึงสามบรรทัด) และโลโก้ `public/logo.svg`
2. ใช้งานบนเว็บ: สร้างห้องจากหน้าแรก, แขกเข้าด้วย QR / ลิงก์แขก / รหัส PIN 6 หลัก, ปิดห้อง, หน้าผู้ดูแล `/admin` (ล็อกอินด้วย Google)
3. รันบนเครื่องตัวเอง: `node server.mjs`, ตัวแปร `PORT`, `HOST`, `DATA_DIR`, ลิงก์เจ้าของที่พิมพ์ตอนเริ่ม, โหมด `?demo=1`
4. นำขึ้น Vercel + Firebase: รายการตัวแปรแวดล้อมทั้งหมดที่ `lib/vercel.mjs` อ่าน (ชื่อ ความหมาย บังคับหรือไม่) โดยไม่ใส่ค่า, กฎ `database.rules.json`, สิ่งที่ต้องเปิดใน Firebase Authentication, `tools/setup.mjs`, `tools/room.mjs` พร้อมตัวอย่างคำสั่ง
5. เพดานจาก `lib/limits.mjs` (ตาราง)
6. ข้อจำกัดที่ควรรู้: ช่องทางค้นหาของ YouTube ไม่เป็นทางการ, ตัวเล่นแบบฝัง, แผนฟรี, ใช้ส่วนตัว
7. โครงสร้างโฟลเดอร์ตามจริง และคำสั่ง `npm test`

### `docs/DESIGN.md`
สัญญาของระบบปัจจุบัน (แทนเนื้อหาเดิมทั้งหมด): รูปข้อมูลใน Firebase (`rooms/<id>/q`, `p`, `/meta`, `/usage`), รูปโทเคน, ตารางสิทธิ์ต่อบทบาท, ทุกเส้นทาง API พร้อมวิธี เนื้อคำขอ คำตอบ และรหัสข้อผิดพลาดที่โค้ดคืนจริง, รายการคำสั่งของ `POST /api/command`, เหตุการณ์ของช่องฟังและวิธีที่หน้าเว็บรวมข้อมูล, ค่า CSP สองชุด, สถานะที่หน้าเว็บแสดง (ไม่มีโทเคน รหัสเปลี่ยน ห้องปิด) · ส่วนที่ยังจริงจากเอกสารเดิม (ค้นหา เติมคำ "คาราโอเกะ", การตรวจเพลงที่ฝังได้, การลากคิว, กรอบขนาดจอ) ให้คงไว้ในรูปย่อ

### `docs/REVIEW.md`
คงรายการเดิม A1–A12, B1–B6, C1–C6 ไว้ แต่เพิ่มคอลัมน์หรือบรรทัด **สถานะ ณ 25 พ.ย. 2026** ต่อข้อ: "แก้แล้ว" (ระบุสั้น ๆ ว่าแก้ด้วยอะไร อ้างไฟล์) / "ยังไม่แก้" / "ไม่เกี่ยวแล้ว" โดยตรวจจากโค้ดจริงทีละข้อ · แทนหัวข้อ D (แผนขึ้นออนไลน์) ด้วยย่อหน้าสั้นที่ชี้ไป `docs/specs/` และ `docs/plans/` · เพิ่มหัวข้อ "ความเสี่ยงใหม่จากการเปิดสร้างห้องสาธารณะ" (คนนอกใช้การค้นหา, การเดา PIN, หน้าผู้ดูแล) พร้อมมาตรการที่มีในโค้ดและสิ่งที่ยังต้องทำนอกโค้ด (กฎ Firewall ของ Vercel, การซ้อมจริง)
