# ใบงาน 11 — ป้ายเตือนเพลงที่เล่นแบบฝังไม่ได้ บนจอหลัก
ผู้รับงาน: agy · โมเดล: gemini-4-neon-high · mode: accept-edits

อ่าน `docs/DESIGN.md` หัวข้อ **"รอบ 6 — ป้ายเตือนเพลงที่เล่นแบบฝังไม่ได้"** ก่อน (สัญญา `GET /api/embeddable` และพฤติกรรมหน้าจออยู่ที่นั่น)
endpoint ฝั่งเซิร์ฟเวอร์อีกคนกำลังเขียนขนานอยู่ — เรียกตามสัญญาได้เลย ไม่ต้องรอ และ**ต้องทนได้ถ้า endpoint ยังไม่มี** (404 → เงียบ)

## เป้าหมาย
ในแท็บ "ผลค้นหา" ของจอหลัก เพลงที่เซิร์ฟเวอร์บอกว่าเล่นแบบฝังไม่ได้จะถูกหรี่ มีป้าย "เล่นที่นี่ไม่ได้" และกดเพิ่มไม่ได้ ผู้ใช้จึงไม่เสียคิวไปกับเพลงที่จะถูกข้าม

## ขอบเขต
- แก้ได้: `public/js/app.js`, `public/styles.css`, `public/js/api.js`, `public/js/demo-data.js`
- ห้ามแตะ: ไฟล์อื่นทั้งหมด (โดยเฉพาะ `public/tokens.css` — class `.pill.is-warn` มีให้แล้ว, `public/js/remote.js`, `public/remote.css`, `lib/**`, `server.mjs`, `test/**`)
- ห้ามเปลี่ยน: ขนาด/ตำแหน่งของ `#stage`, `#nowbar`, `#sidebar`; id ที่มีอยู่; พฤติกรรมอื่น · ข้อมูลจากภายนอกใส่ด้วย `textContent`/`setAttribute`

## วิธีทำงาน
แก้ไฟล์ด้วยเครื่องมือแก้ไฟล์เท่านั้น · sandbox ไม่มีเครือข่าย/เบราว์เซอร์ · ใช้แค่ `node --check public/js/app.js public/js/api.js public/js/demo-data.js`

## งาน
1. `api.js`: เพิ่ม `fetchEmbeddable(ids, { signal })` → เรียก `/api/embeddable?ids=<คั่นด้วยจุลภาค>`; คืน object `{ id: true|false|null }`; HTTP ไม่ใช่ 200 หรือเครือข่ายล้ม → คืน `{}` (ไม่ throw)
2. `app.js`: `const embedFlags = new Map()` ระดับโมดูล
   - หลังผลค้นหาชุดใหม่แสดง: เก็บ id ที่ยังไม่มีใน `embedFlags` (สูงสุด 30) → `fetchEmbeddable` → ใส่เฉพาะค่าที่เป็น `true`/`false` ลง map → ถ้าผลค้นหาที่แสดงอยู่ยังเป็นชุดเดิม ให้ `renderResultsPanel()` ใหม่ · ไม่มี id ใหม่ → ไม่เรียก · ห้ามบล็อกการแสดงผลค้นหาระหว่างรอ
   - `renderResultsPanel`: แผ่นปกที่ `embedFlags.get(id) === false` → class `is-blocked`; ป้าย `<span class="pill is-warn poster-inq">เล่นที่นี่ไม่ได้</span>` แทนป้าย "ในคิวแล้ว" (ไม่แสดงสองป้ายพร้อมกัน); ปุ่ม "เข้าคิว" / "เล่นถัดไป" / "เล่นเลย" ของแผ่นนั้น `disabled` และ `aria-label` ต่อท้าย " (เล่นที่นี่ไม่ได้)"
   - แท็บ "ร้องไปแล้ว" และคิว: ไม่เปลี่ยน
3. โหมด `?demo=1`: ไม่เรียก endpoint; ตั้ง `embedFlags` ของเพลงตัวอย่างลำดับที่ 8 (ตัวสุดท้าย ซึ่งไม่อยู่ในคิวตัวอย่าง) เป็น `false` ไว้ล่วงหน้า เพื่อให้หัวหน้าดูหน้าตาป้ายได้
4. แก้ข้อความ toast ตอนตัวเล่นแจ้ง error ให้ตรงความจริงทุกกรณี: จาก "เพลงนี้เล่นในหน้านี้ไม่ได้ (เจ้าของปิดการฝัง) กำลังข้ามไปเพลงถัดไป" เป็น **"เพลงนี้เล่นในหน้านี้ไม่ได้ กำลังข้ามไปเพลงถัดไป"**
5. `styles.css`:
   ```
   .tile.is-blocked .poster img { filter: grayscale(0.85) brightness(0.5); }
   .tile.is-blocked .ttl, .tile.is-blocked .ch { color: var(--text-muted); }
   .tile.is-blocked:hover, .tile.is-blocked:focus-within { transform: none; border-color: var(--line); box-shadow: none; }
   ```
   (ชื่อ class ของปก/ชื่อเพลง/ช่องให้ใช้ตามที่มีอยู่จริงในไฟล์ ถ้าต่างจากตัวอย่าง)

## ขนาดจอ
1440x900, 1024x768, 844x390, 390x844, กว้าง 360 — ป้าย "เล่นที่นี่ไม่ได้" ต้องไม่ล้นแผ่นปกที่แคบสุด 138px (ตัวอักษร 13px, `white-space:nowrap`; ถ้ากว้างเกินปกให้ย่อ padding ซ้ายขวาของป้ายเหลือ 6px ด้วย `@container`)

## กลไกการจัดวาง
ไม่เปลี่ยน — ป้ายอยู่ตำแหน่งเดียวกับป้าย "ในคิวแล้ว" (absolute มุมซ้ายบนของปก)

## เทสต์กรอบ
ไม่มีในใบนี้ — หัวหน้าตรวจในเบราว์เซอร์ด้วยโหมด demo และเซิร์ฟเวอร์ทดสอบ

## สถานะอื่น
ปุ่มที่ `disabled` ต้องเห็นว่าจาง (tokens.css มี `:disabled` ให้แล้ว) และโฟกัสด้วยคีย์บอร์ดข้ามไป · `prefers-reduced-motion`: tokens.css จัดการแล้ว

## ภาพที่ต้องได้
แผ่นปกที่ถูกบล็อก: ปกเกือบขาวดำและมืดลงครึ่งหนึ่ง, ป้ายสีทองตัวอักษรเข้มอ่านชัด (contrast ≥ 4.5), ไม่ยกตัวตอน hover

## ภาษาไทย
ห้ามตัดกลางคำ: "เล่นที่นี่ไม่ได้"

## การตรวจ
`node --check` ผ่านกับสามไฟล์ JS ที่แก้
