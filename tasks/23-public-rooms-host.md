## รายละเอียดที่ต้องตรง
- `session.js` เพิ่ม `export function saveToken(role, token, { storage } = {})`: ตรวจรูปและบทบาทเหมือน `takeToken` (ไม่ผ่านคืน `null`) เก็บลงคีย์เดิม (หรือหน่วยความจำถ้า storage ใช้ไม่ได้) คืน `{ token, roomId }` · เพิ่มเทสต์: เก็บแล้ว `takeToken` อ่านได้, โทเคนผิดบทบาทไม่ถูกเก็บ, storage ที่โยนข้อผิดพลาดยังใช้ได้ในหน้าเดียวกัน
- `api.js` เพิ่ม `export async function getConfig({ signal } = {})` (GET `/api/config` คืนวัตถุ) และ `export async function createRoom(name, { signal } = {})` (POST `/api/rooms` เนื้อ `{ name }` ไม่มีหัว `Authorization` คืน `{ roomId, name, ownerToken, ownerUrl }`; ข้อผิดพลาดมี `code` และ `status` แบบเดียวกับฟังก์ชันอื่น)
- สถานะ `no_token` ของ `#room-gate` เปลี่ยนเป็น **การ์ดสร้างห้อง**: โลโก้เป็ด (`<img src="/logo.svg">` 72px), หัวข้อ "สร้างห้องคาราโอเกะ", คำอธิบายหนึ่งบรรทัด ("ตั้งชื่อห้อง แล้วให้เพื่อนสแกน QR เพื่อสั่งเพลงจากมือถือ"), ช่องชื่อห้อง (`maxlength="40"`, placeholder "เช่น บ้านคุณยาย", `autocomplete="off"`, มี `<label>`), ปุ่ม `.btn-neon` "สร้างห้อง", บรรทัดเล็ก "มีลิงก์ห้องอยู่แล้ว? เปิดลิงก์นั้นได้เลย"
  - ตอนเปิดการ์ดเรียก `getConfig()`: `createEnabled === false` → ซ่อนฟอร์ม แสดง "ตอนนี้ปิดรับการสร้างห้องใหม่" · เรียกไม่ได้ → ยังแสดงฟอร์ม
  - ส่งฟอร์ม (กดปุ่มหรือ Enter): ชื่อหลังตัดช่องว่างว่าง → แจ้ง "ใส่ชื่อห้องก่อน" และโฟกัสช่อง · ระหว่างรอปิดปุ่มและแสดง "กำลังสร้าง…" · สำเร็จ → `saveToken('o', ownerToken)` แล้ว `window.location.reload()` (หน้าที่โหลดใหม่จะเข้าห้องเองจากโทเคนที่เก็บ) · `saveToken` คืน `null` → แจ้งข้อผิดพลาดทั่วไป
  - ข้อความตามรหัส: `bad_name` → "ชื่อห้องใช้ไม่ได้ (ยาวได้ไม่เกิน 40 ตัวอักษร)" · `create_disabled` → "ตอนนี้ปิดรับการสร้างห้องใหม่" · `rooms_full` → "ห้องเต็มแล้ว ลองใหม่ภายหลัง" · `too_many_rooms` → "มีคนสร้างห้องเยอะเกินไปในชั่วโมงนี้ ลองใหม่อีกสักครู่" · อื่น ๆ หรือเครือข่ายล้ม → "สร้างห้องไม่สำเร็จ ลองอีกครั้ง" · ข้อความแสดงในการ์ดด้วย `role="alert"`
- สถานะ `bad_key` และ `gone`: คงข้อความเดิม เพิ่มปุ่ม `.btn-neon` "สร้างห้องใหม่" ที่สลับไปการ์ดสร้างห้อง (ไม่โหลดหน้าใหม่)
- แท็บ "มือถือ": เพิ่มปุ่ม "ปิดห้อง" ใต้ปุ่ม "เปลี่ยนรหัสแขก" แบบกดยืนยันสองจังหวะเหมือนกัน (จังหวะสอง "กดอีกครั้งเพื่อปิดห้อง") พร้อมคำอธิบายสั้น "คิวและประวัติของห้องนี้จะหายทั้งหมด" → `dispatch({ type: 'closeRoom' })` สำเร็จ → หยุดตัวเล่น, `sync.stop()`, `forgetToken('o')`, แสดงการ์ดสร้างห้อง พร้อมข้อความ "ปิดห้องแล้ว" · ล้มเหลว → toast "ปิดห้องไม่สำเร็จ ลองอีกครั้ง"
- หลังปิดห้องเอง สถานะ `gone` ที่ตามมาจากช่องฟังต้องไม่ทับการ์ดสร้างห้องด้วยจอ "ห้องนี้ถูกปิดแล้ว"
- การ์ดต้องใช้ได้ด้วยคีย์บอร์ดล้วน: โฟกัสเริ่มที่ช่องชื่อห้อง, Enter ส่งฟอร์ม, ปุ่มมีสถานะ `disabled` ระหว่างรอ
- การ์ดอยู่กลางจอทุกขนาด (1440×900, 1024×768, 844×390, 390×844) ไม่ล้นและไม่มีแถบเลื่อนแนวนอน กว้างสุด 440px
