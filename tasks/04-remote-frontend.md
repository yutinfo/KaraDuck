## งาน A — `public/js/sync.js` (ใช้ร่วมทั้งสองหน้า)
```
createSync({ key = '', onState, onControl, onStatus })   // key ว่าง = จอหลัก (เครื่องเดียวกัน ไม่ต้องมีรหัส)
  .start()              // เปิด EventSource('/api/events' + (key ? '?k=' + encodeURIComponent(key) : ''))
                        //   event 'state' → onState(snapshot) · event 'control' → onControl(data.action)
                        //   onopen → onStatus('online') · onerror → onStatus('offline') (EventSource ต่อใหม่เอง)
  .send(cmd)            // POST /api/command (+ ?k=) header Content-Type: application/json, body JSON
                        //   คืน Promise; HTTP ไม่ใช่ 200 → reject Error ที่มี .code จาก body และ .status
  .stop()
```
ครั้งแรกที่ต่อไม่ได้เพราะรหัสผิด EventSource บอกสถานะไม่ได้ → ก่อน `start()` ให้ `fetch('/api/state' + k)` หนึ่งครั้ง: 401 → `onStatus('bad_key')` และไม่เปิด EventSource

## งาน B — จอหลัก (`app.js`, `index.html`, `styles.css`)
1. ลบการอ่าน/เขียน `localStorage` คีย์ `karaoke.state.v1` ทั้งหมด · state มาจาก `onState(snapshot)` เท่านั้น
2. ทุกการกระทำที่เคยเรียกฟังก์ชัน store ตรง ๆ เปลี่ยนเป็น `dispatch(cmd)`:
   - โหมดปกติ → `sync.send(cmd)`; ล้มเหลว → toast "ส่งคำสั่งไม่สำเร็จ ลองอีกครั้ง"
   - โหมด `?demo=1` → `state = applyCommand(state, cmd)` (import จาก `./commands.js`) แล้ว render; ไม่ต่อ `/api/events`, ไม่ส่งคำสั่ง
   คำสั่งที่ใช้: `enqueue`/`enqueueNext`/`playNow` (`song`), `playFromQueue`/`remove`/`moveToTop` (`qid`), `move` (`qid`,`delta`), `advance`, `clearQueue`, `clearHistory`
   toast ข้อความเดิม ("เพิ่ม … เข้าคิวลำดับที่ N") คำนวณจาก state ปัจจุบันก่อนส่ง
3. ตัวเล่น ตาม "พฤติกรรมจอหลัก (รอบ 2)" ใน DESIGN.md: เก็บ `lastQid`; Snapshot แรก → `cue`; `current.qid` เปลี่ยนภายหลัง → `load`; null → จอว่าง
   `onEnded` → `dispatch({type:'advance', qid})` · `onError` → toast เดิม แล้ว 2.5 วินาที `dispatch({type:'advance', qid, skipHistory:true})`
   `onState` ของตัวเล่น → `dispatch({type:'report', playerState})` (ไม่ส่งในโหมด demo) · `onControl('toggle'|'restart')` → `player.toggle()` / `player.restart()`
   ปุ่ม "ข้ามเพลง" → `dispatch({type:'advance', qid: current.qid})` · ปุ่มเล่น–หยุด/เริ่มใหม่ของจอหลักสั่งตัวเล่นตรง ๆ เหมือนเดิม
4. เบราว์เซอร์บล็อกเล่นอัตโนมัติ: หลัง `load` 4 วินาที ถ้าสถานะตัวเล่นยังไม่ใช่ `playing`/`buffering` → แสดงข้อความใน `#nowbar` (แทนบรรทัด "ถัดไป"): "กด ▶ หนึ่งครั้งเพื่อเปิดเสียง หลังจากนั้นเพลงจะเล่นต่อเองจากมือถือได้" จนกว่าจะเล่น
5. แสดงชื่อคนขอ: ถ้าเพลงมี `by` → ต่อท้ายบรรทัดช่องเป็น `<ช่อง> · ขอโดย <by>` ทั้งใน `#nowbar`, การ์ด "กำลังร้อง", แถวคิว และแถวประวัติ
6. แท็บที่ 4 "มือถือ": `#tab-remote` / `#panel-remote` (role tab/tabpanel เหมือนแท็บอื่น, `&tab=remote` ใน demo ก็เปิดได้)
   - โหลด `GET /api/remote-info` ครั้งแรกที่เปิดแท็บ (และตอนเริ่มหน้า เพื่อใช้ข้อ 7)
   - available: หัวข้อ "สั่งเพลงจากมือถือ" → `<img id="remote-qr" src="/api/qr.svg" alt="QR สำหรับเปิดหน้าสั่งเพลง">` ขนาด 220×220px ในกรอบพื้นขาว `#fff` padding 12px มุม 12px (กรอบรวม 244×244 จัดกลาง) → ลิงก์เป็นข้อความ (`#remote-url`, ฟอนต์ monospace 14px, `overflow-wrap:anywhere`, เลือกคัดลอกได้) → ขั้นตอน 3 ข้อ: "1. ต่อ Wi-Fi วงเดียวกับเครื่องนี้" "2. สแกน QR ด้วยกล้องมือถือ" "3. ค้นหาเพลงแล้วกด เข้าคิว"
   - ไม่ available หรือโหลดไม่ได้: "ไม่พบเครือข่าย Wi-Fi ของเครื่องนี้ ต่อ Wi-Fi แล้วเปิดหน้านี้ใหม่"
   - แถบแท็บมี 4 แท็บ: เมื่อ `--side` ≤ 360px แท็บนี้แสดงเฉพาะไอคอนมือถือ (กว้าง 44px, `aria-label="สั่งเพลงจากมือถือ"`); กว้างกว่านั้นแสดงไอคอน + คำว่า "มือถือ" · ป้ายแท็บทุกอันต้องไม่ตัดบรรทัดและไม่ล้นที่ sidebar 320px
7. จอว่าง (`#stage` ตอน current เป็น null) เฉพาะโหมด desktop: วางไมโครโฟน+ข้อความเดิมไว้ซ้าย และ QR ขนาด 140×140px (กรอบขาว padding 8px) พร้อมข้อความ "สแกนเพื่อสั่งเพลงจากมือถือ" ไว้ขวา เว้นช่องกลาง 40px จัดกึ่งกลางทั้งกลุ่ม; ทั้งกลุ่มต้องอยู่ในกรอบ stage 604×340 ได้โดยไม่ล้น · โหมด compact/stacked ไม่แสดง QR ในจอว่าง · ไม่ available → ไม่แสดง QR
8. สถานะการเชื่อมต่อ: `onStatus('offline')` → แถบเล็กบนสุดของ `#sidebar` "กำลังเชื่อมต่อเซิร์ฟเวอร์ใหม่…" (สี `#ffd166` บนพื้น `#1e1733`); `online` → ซ่อน
9. `?demo=1` ทำงานเหมือนเดิม (ไม่แตะ localStorage, ไม่ต่อ SSE) — เพิ่ม `by: "เก่ง"` ให้เพลงที่ 2 และ `by: "มายด์"` ให้เพลงที่ 3 ใน demo-data เพื่อดูการแสดงชื่อคนขอ

## งาน C — หน้ามือถือ (`remote.html`, `remote.css`, `remote.js`)
`remote.html` โหลด `styles.css` (เอาตัวแปรสี ปุ่ม `.btn` ฯลฯ) ตามด้วย `remote.css`; `<body class="remote">` · ห้ามใช้ id ของจอหลัก (`#app`, `#stage`, `#sidebar` …) · title "สั่งเพลง — ร้องเลย"
`remote.css` ต้องล้างกติกาโหมด desktop/compact ของจอหลัก: `body.remote{height:auto; min-height:100dvh; overflow:visible}` ในทุก media query (หน้าเลื่อนแนวตั้งตามปกติทุกขนาดจอ)

โครง (คอลัมน์เดียว กว้างสูงสุด 560px จัดกลาง, padding ซ้ายขวา 16px):
1. `#r-now` — `position:sticky; top:0; z-index:10`, พื้นทึบ `#151024`, สูง 72px, เส้นล่าง 1px `rgba(255,61,154,.35)`:
   ซ้าย: ป้าย "กำลังร้อง" + ชื่อเพลง (บรรทัดเดียว ตัด …, Kanit 16px) + บรรทัดรอง 13px (`ขอโดย <by>` หรือชื่อช่อง; ไม่มีเพลง → "ยังไม่มีเพลงกำลังเล่น")
   ขวา: ปุ่มไอคอน 44×44px สามปุ่ม "เริ่มใหม่" (`control restart`), "เล่น–หยุด" (`control toggle`; ไอคอนตาม `snapshot.playerState`), "ข้ามเพลง" (`advance` พร้อม `qid` ปัจจุบัน; กดแล้วเปลี่ยนเป็น "แน่ใจ?" 3 วินาที กดอีกครั้งจึงข้าม) — ไม่มีเพลง → disabled ทั้งสาม
2. `#r-name` — ช่อง "ชื่อคนสั่งเพลง (ไม่ใส่ก็ได้)" `maxlength="20"`, สูง 44px; เก็บใน `localStorage` คีย์ `karaoke.remote.name` (ครอบ try/catch); ค่านี้ส่งเป็น `song.by` ทุกครั้งที่เพิ่มเพลง
3. `#r-search-form` + `#r-search-input` — เหมือนช่องค้นของจอหลัก (ป้าย "คาราโอเกะ", สูง 52px, ปุ่ม "ค้นหา"); `#r-search-note` แสดง `ค้นหา: <query>`; เรียก `/api/search?q=…&k=<รหัส>`
4. แท็บ `#r-tab-results` "ผลค้นหา" / `#r-tab-queue` "คิว N" (แถบแท็บสูง 44px, role tablist)
5. `#r-panel-results` — แถวผลค้นหา: ภาพปก 112×63, ชื่อ 2 บรรทัด, ช่อง, ป้าย "ในคิวแล้ว", ปุ่ม "เข้าคิว" (ปุ่มหลัก ยืดเต็มที่เหลือ) + "เล่นถัดไป" (ปุ่มรอง) · สถานะ กำลังโหลด (โครงร่าง 6 แถว) / ไม่พบ / ผิดพลาด+ลองใหม่ / ยังไม่ค้น ("พิมพ์ชื่อเพลงหรือศิลปิน ระบบจะเติม "คาราโอเกะ" ให้เอง")
6. `#r-panel-queue` — การ์ด "กำลังร้อง" + หัวรายการ `N เพลง · รวม <เวลา>` + แถวคิว: เลขลำดับสีทอง, ภาพปก 80×45, ชื่อ, `ความยาว · ขอโดย <by>`, ปุ่ม "ขึ้นบนสุด" (`moveToTop`) และ "ลบ" (`remove`) · คิวว่าง → "คิวว่าง ค้นหาเพลงแล้วกดเข้าคิวได้เลย" · ไม่มีปุ่มล้างคิว (เซิร์ฟเวอร์ไม่อนุญาตจากมือถือ)
7. `#r-toasts` — `position:fixed` ล่างกลาง ห่างขอบ 16px (toast เหมือนจอหลัก)
8. `#r-status` — แถบแจ้ง: `offline` → "กำลังเชื่อมต่อใหม่…" · `bad_key` → ซ่อนทุกส่วนอื่น แสดงเต็มหน้า "ลิงก์นี้ใช้ไม่ได้แล้ว สแกน QR ที่จอหลักอีกครั้ง"
รหัสห้อง: อ่านจาก `?k=` ของ URL; ไม่มี → ถือเป็น `bad_key` · คำสั่งล้มเหลว (`403`/`400`/เครือข่าย) → toast "ส่งคำสั่งไม่สำเร็จ ลองอีกครั้ง"; `401` → เข้าสถานะ `bad_key`
ฟังก์ชันจัดรูปเวลา import จาก `./store.js` (`formatDuration`, `totalDurationSec`)
