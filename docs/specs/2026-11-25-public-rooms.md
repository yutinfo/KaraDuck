# แบบระบบ (ส่วนเพิ่ม): สร้างห้องจากหน้าเว็บ และหน้าผู้ดูแล

วันที่ 25 พ.ย. 2026 · ต่อจาก `docs/specs/2026-11-25-online-design.md` (เรียกว่า "แบบหลัก")
เจ้าของตัดสินแล้ว: ใครก็สร้างห้องได้จากหน้าแรกแบบ Kahoot และมีส่วนผู้ดูแลไว้ปิดห้อง
ข้อนี้ยกเลิกข้อ "ไม่ทำ: ให้คนทั่วไปสร้างห้องเอง" ในแบบหลัก ส่วนอื่นของแบบหลักยังใช้ตามเดิม

## 1. พฤติกรรมที่ผู้ใช้เห็น

- เปิด `https://<เว็บ>/` บนเครื่องที่ยังไม่มีห้อง → เห็นการ์ด "สร้างห้องคาราโอเกะ": ช่องชื่อห้อง + ปุ่ม "สร้างห้อง" กดแล้วเครื่องนั้นกลายเป็นจอหลักของห้องใหม่ทันที แขกสแกน QR เหมือนเดิม
- เครื่องที่จำห้องไว้แล้วเข้าห้องเดิมเหมือนเดิม ในแท็บ "มือถือ" ของจอหลักมีปุ่ม "ปิดห้อง" (กดยืนยันสองจังหวะ)
- ห้องถูกปิดหรือลิงก์ใช้ไม่ได้ → จอแจ้งเหตุ พร้อมปุ่ม "สร้างห้องใหม่"
- `https://<เว็บ>/admin` → หน้าผู้ดูแล: วางกุญแจผู้ดูแลครั้งเดียวต่อเครื่อง แล้วเห็นทุกห้อง ปิดห้องไหนก็ได้ ออกลิงก์เจ้าของใหม่ได้ และเปิด/ปิดการรับสร้างห้องได้
- ห้องที่ไม่มีการใช้งานเกิน 24 ชั่วโมงถูกปิดเอง

## 2. เพดาน (อยู่ใน `lib/limits.mjs`)

| ค่า | ตัวเลข | เมื่อเกิน |
|---|---|---|
| `MAX_ROOMS` ห้องที่เปิดพร้อมกัน | 30 | `503 rooms_full` |
| `CREATES_PER_HOUR` ห้องที่สร้างได้ต่อชั่วโมงนาฬิกา (รวมทั้งเว็บ) | 20 | `429 too_many_rooms` |
| `IDLE_MS` อายุห้องที่ไม่มีการใช้งาน | 24 ชั่วโมง | ห้องถูกลบตอนมีการสร้างห้องหรือตอนผู้ดูแลเปิดดูรายการ |
| `SEARCHES_PER_HOUR` การค้นหาต่อห้องต่อชั่วโมงนาฬิกา | 120 | `429 search_budget` |

สวิตช์: ผู้ดูแลปิดการรับสร้างห้องได้จากหน้า `/admin` (เก็บในฐานข้อมูล) และตัวแปร `CREATE_DISABLED=1` ปิดแบบบังคับ
ห้องที่ผู้ดูแลสร้างผ่าน `/api/admin` ไม่ติดเพดานจำนวนและความถี่

## 3. ข้อมูล

- ข้อมูลห้อง (`q`) เพิ่ม `createdAt` และ `updatedAt` (เวลา ms) · `updatedAt` เปลี่ยนทุกครั้งที่เขียน `q` · ห้องเก่าที่ไม่มีสองค่านี้ถือเป็น 0 และ **ไม่ถูกปิดอัตโนมัติ** จนกว่าจะมีคำสั่งแรกมาประทับเวลา (ห้อง "บ้านเรา" ที่ใช้อยู่ต้องไม่หาย)
- ห้องหมดอายุเมื่อ `updatedAt > 0` และ `now - updatedAt > IDLE_MS`
- `/meta` (ข้อความ JSON ก้อนเดียว เขียนแบบมีเงื่อนไข ETag): `{ createEnabled: boolean, hour: <เลขชั่วโมงนาฬิกา>, creates: <จำนวนที่สร้างในชั่วโมงนั้น> }` ไม่มี → `{ createEnabled: true, hour: 0, creates: 0 }`
- `/usage/<roomId>` (ข้อความ JSON เขียนทับได้เลย): `{ hour, searches }`
- กฎ Firebase ไม่ต้องแก้: `/meta` และ `/usage` อ่านเขียนได้เฉพาะบัญชีบริการ

ชั้นเก็บข้อมูลเพิ่ม (ทั้ง `file` และ `rtdb`):

```js
readMeta()                    // → Promise<{ text: string | null, etag: string }>
writeMeta(text, etag)         // → Promise<boolean>
readUsage(roomId)             // → Promise<string | null>
writeUsage(roomId, text)      // → Promise<void>
// deleteRoom(roomId) ลบ /usage/<roomId> ด้วย
```

## 4. API ที่เพิ่มหรือเปลี่ยน

| เส้นทาง | สิทธิ์ | พฤติกรรม |
|---|---|---|
| `POST /api/rooms` | ไม่ต้อง | เนื้อ `{ name }` → `200 { roomId, name, ownerToken, ownerUrl }` · ลำดับตรวจ: JSON และขนาด (415/413) → ชื่อ (`400 bad_name`) → สวิตช์ (`403 create_disabled`) → ลบห้องหมดอายุ → จำนวนห้อง (`503 rooms_full`) → ความถี่ (`429 too_many_rooms`) → สร้าง |
| `GET /api/config` | ไม่ต้อง | เพิ่ม `createEnabled` (แคชในหน่วยความจำได้ไม่เกิน 30 วินาที) |
| `POST /api/command` `{ type: "closeRoom" }` | เจ้าของ | ลบห้องและ usage → `200 { ok: true, closed: true }` · แขก → `403 owner_only` |
| `GET /api/search` | แขก/เจ้าของ | นับทุกคำขอที่ผ่านการตรวจสิทธิ์ลง `/usage/<roomId>` เกินเพดาน → `429 search_budget` |
| `POST /api/admin` `list` | ผู้ดูแล | ลบห้องหมดอายุก่อน แล้วคืน `{ createEnabled, limits, rooms: [{ roomId, name, rev, queueLength, current, createdAt, updatedAt }] }` (`current` คือชื่อเพลงที่กำลังเล่นหรือ `null`) |
| `POST /api/admin` `{ action: "setCreate", enabled }` | ผู้ดูแล | เขียน `/meta` → `{ createEnabled }` |

`create`, `delete`, `rotateOwner` ของผู้ดูแลคงเดิม

## 5. หน้าเว็บ

- จอหลัก: การ์ดสร้างห้องแทนจอ "ต้องเปิดจากลิงก์ห้อง" · หลังสร้างสำเร็จเก็บ `ownerToken` แล้วเข้าห้องนั้น · ปุ่ม "ปิดห้อง" · ปุ่ม "สร้างห้องใหม่" บนจอแจ้งว่าห้องถูกปิดหรือลิงก์ใช้ไม่ได้ · `createEnabled` เป็น `false` → แสดงว่าปิดรับการสร้างห้องอยู่และไม่แสดงฟอร์ม
- หน้ามือถือ: ไม่เปลี่ยน
- หน้าผู้ดูแล: `public/admin.html`, `public/admin.css`, `public/js/admin.js` ใช้ชิ้นส่วนจาก `public/tokens.css` · กุญแจรับจากช่องแบบรหัสผ่านหรือจาก `#k=<กุญแจ>` เก็บใน `localStorage` คีย์ `karaoke.admin` ส่งในหัว `Authorization: Bearer` · 401 → ล้างกุญแจและกลับไปหน้ากรอก

## 6. ที่ยังไม่ทำ

- เข้าห้องด้วยรหัสตัวเลขสั้นแบบ PIN ของ Kahoot (แขกยังเข้าด้วย QR หรือลิงก์แขก)
- เปลี่ยนชื่อห้องหลังสร้าง
- จำกัดความถี่แยกตาม IP ในโค้ด (ใช้กฎของ Vercel Firewall ตามแบบหลัก)

## 7. ความเสี่ยงที่เจ้าของรับทราบ

เว็บเปิดสาธารณะ: คนนอกสร้างห้องและใช้การค้น YouTube ผ่านเว็บนี้ได้ภายในเพดานข้อ 2 ถ้า YouTube จำกัด IP ของ Vercel เพราะการใช้จากคนนอก ทุกห้องจะค้นไม่ได้ ทางถอยคือปิดการรับสร้างห้องจากหน้าผู้ดูแล และโหมดรันบนเครื่องตามแบบหลัก
