# แผนงาน: ร้องเลย ออนไลน์ (Vercel + Firebase, หลายห้อง)

> **วิธีทำงาน:** Claude เป็นหัวหน้าทีม เขียนใบงานใน `tasks/` จากแต่ละงานในแผนนี้ ส่งให้ Codex หรือ agy ตามที่ระบุ แล้วตรวจผลเอง (รันเทสต์ อ่าน diff เปิดเบราว์เซอร์)
> ทุกงานทำแบบเขียนเทสต์ก่อน ช่องทำเครื่องหมาย `- [ ]` ใช้ติดตามความคืบหน้า

**เป้าหมาย:** สองบ้านร้องคาราโอเกะพร้อมกันบนเว็บเดียว แต่ละบ้านมีห้อง คิว และสิทธิ์ของตัวเอง

**สถาปัตยกรรม:** หน้าเว็บนิ่งบน Vercel ฟังข้อมูลห้องจาก Firebase Realtime Database ด้วย `EventSource` (อ่านอย่างเดียว) ทุกการเขียนผ่านฟังก์ชันบน Vercel ที่ตรวจโทเคนแบบเซ็นชื่อแล้วเขียนด้วย REST แบบมีเงื่อนไข ETag
ตัวจัดการ API ชุดเดียวกันรันบนเครื่องได้ด้วยชั้นเก็บข้อมูลแบบไฟล์และช่องฟังจำลอง

**เทคโนโลยี:** Node 22 · ES modules · ไม่มี dependency จาก npm · ไม่มี build · `node --test`

**แบบ:** `docs/specs/2026-11-25-online-design.md` (ผู้ทำงานทุกคนอ่านคู่กับแผนนี้ เลขข้อ "§" ในแผนหมายถึงข้อในแบบ)

## ข้อกำหนดร่วม

- ห้ามเพิ่ม dependency จาก npm และห้ามเพิ่มขั้น build
- ห้ามแตะเซิร์ฟเวอร์ที่รันอยู่ที่พอร์ต 8791 และโฟลเดอร์ `data/` ของมัน งานทั้งหมดทำในสำเนาแยก (งาน 0) เซิร์ฟเวอร์ทดสอบใช้พอร์ต 8792
- ความลับห้ามอยู่ในไฟล์ที่ git ติดตาม: `ROOM_SECRET`, `ADMIN_KEY`, `FIREBASE_PRIVATE_KEY`
- ไม่มีสิทธิ์ใดได้จาก IP ทุกสิทธิ์มาจากโทเคนในหัว `Authorization: Bearer`
- รูปคำขอ/คำตอบภายใน: `request = { method, url, headers, body }` (`headers` เป็นวัตถุชื่อตัวเล็ก, `body` เป็นข้อความ) → `response = { status, headers, body }`
- ทุกคำตอบของ API เป็น JSON ข้อผิดพลาดเป็น `{ "error": "<รหัส>" }` ไม่ใส่หัว CORS
- ชุดอักษรของ `roomId`: `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` ยาว 16 ตัว
- เพดาน: คิวไม่เกิน 200 เพลง · เนื้อคำขอไม่เกิน 16 KB · ช่องฟังบนเครื่องไม่เกิน 50 · ลองเขียนซ้ำเมื่อ ETag ชนไม่เกิน 5 รอบ
- ข้อความที่ผู้ใช้เห็นเป็นภาษาไทย น้ำเสียงเดียวกับของเดิม ใส่ข้อมูลภายนอกลงหน้าเว็บด้วย `textContent`/`setAttribute` เท่านั้น
- กรอบขนาดจอเดิมต้องไม่เปลี่ยน (ตัวเลขใน `tasks/02-frontend.md`, `tasks/04-remote-frontend.md`, `tasks/05-glass-host.md`)
- โหมด `?demo=1` ต้องทำงานเหมือนเดิมโดยไม่ต้องมีโทเคน
- commit เฉพาะในเครื่อง ไม่ push จนกว่าเจ้าของสั่ง

## จุดที่ต้องจับตาตอนรีวิว

กรณีที่แบบบอกเป็นนัยแต่หลุดง่าย เทสต์ของแต่ละข้ออยู่ในงานที่ระบุ:
1. แขกสองคนเพิ่มเพลงพร้อมกัน → ต้องเข้าคิวครบทั้งสองเพลง (งาน 4)
2. โทเคนของห้อง ก ใช้กับห้อง ข หรือโทเคนแขกถูกวางในลิงก์เจ้าของ (`#o=`) → ต้องถูกปฏิเสธ จอหลักต้องไม่ทำงานด้วยสิทธิ์แขก (งาน 4, งาน 9)
3. ห้องถูกลบขณะที่จอเปิดอยู่ → จอแสดงว่าห้องถูกปิด คำสั่งตอบ 404 ไม่ค้างและไม่วนต่อใหม่ไม่สิ้นสุด (งาน 5, งาน 8)
4. จอหลักหลับแล้วตื่น → ต่อช่องฟังใหม่ ไม่ทำคำสั่งหยุด/เล่นย้อนหลัง และการส่ง `advance` ซ้ำไม่ข้ามเพลงเกิน (งาน 8, งาน 9)
5. เปิดลิงก์ห้องใหม่บนเบราว์เซอร์ที่จำโทเคนห้องเก่าไว้ หรือ `localStorage` ใช้ไม่ได้ (โหมดส่วนตัว) → ใช้โทเคนจากลิงก์ล่าสุด และยังทำงานได้ตลอดการเปิดหน้าครั้งนั้น (งาน 8)

### งาน 1: โทเคน (Codex)

**ไฟล์:** สร้าง `lib/tokens.mjs` · เทสต์ `test/tokens.test.mjs`

**ส่งออก:**
```js
export const ROOM_ID_ALPHABET = 'ABCDEFGHJKLMNPQRSTUVWXYZ23456789';
export function makeRoomId(randomInt = crypto.randomInt)            // → ข้อความ 16 ตัว
export function signToken(secret, { roomId, role, epoch })          // → `${roomId}.${role}${epoch}.${sig}`
export function verifyToken(secret, token)                          // → { roomId, role, epoch } | null
export function bearerToken(headers)                                // → ข้อความหลัง "Bearer " | null
```
- `sig` = base64url ของ 16 ไบต์แรกของ HMAC-SHA256(`secret`, `${roomId}.${role}${epoch}`) ยาว 22 ตัว เทียบด้วย `timingSafeEqual`
- `roomId` ต้องตรง `^[A-HJ-NP-Z2-9]{16}$` · `role` คือ `o` หรือ `g` · `epoch` ตรง `^[1-9]\d{0,8}$`

- [ ] เขียนเทสต์ให้ล้มก่อน:
```js

  const t = signToken('s', { roomId: 'ABCDEFGHJKLMNPQR', role: 'g', epoch: 3 });
  assert.match(t, /^ABCDEFGHJKLMNPQR\.g3\.[\w-]{22}$/);
  assert.deepEqual(verifyToken('s', t), { roomId: 'ABCDEFGHJKLMNPQR', role: 'g', epoch: 3 });
});
test('ปฏิเสธโทเคนที่ถูกแก้', () => {
  const t = signToken('s', { roomId: 'ABCDEFGHJKLMNPQR', role: 'g', epoch: 3 });
  for (const bad of [t.replace('.g3.', '.o3.'), t.replace('.g3.', '.g4.'), t.replace('ABCD', 'ABCE'),
    t.slice(0, -1), `${t}x`, '', null, 42, 'a.b', 'ABCDEFGHJKLMNPQR.g03.x', 'ABCDEFGHJKLMNPQR.g0.x'])
    assert.equal(verifyToken('s', bad), null);
  assert.equal(verifyToken('other', t), null);
});
test('makeRoomId ใช้ชุดอักษรที่กำหนด', () => assert.match(makeRoomId(), /^[A-HJ-NP-Z2-9]{16}$/));
test('bearerToken', () => {
  assert.equal(bearerToken({ authorization: 'Bearer abc' }), 'abc');
  assert.equal(bearerToken({ authorization: 'Basic abc' }), null);
  assert.equal(bearerToken({}), null);
});
```

  - `clearQueue`, `clearHistory` (เจ้าของ) และคำสั่งคิวที่เหลือ → `applyCommand`

  - สถานะไม่เปลี่ยน → ไม่เขียน
  - สำเร็จ → 200 `{ ok: true, rev }`
- `command`: `Content-Type` ไม่ใช่ `application/json` → 415 `bad_content_type` · `body` เกิน 16 KB → 413 `too_large` · ไม่ใช่ POST → 405
- `config` → `{ mode, db: dbUrl, origin: origin(request) }` ไม่ต้องมีโทเคน
- `room` → `{ roomId, name, role }` เจ้าของได้เพิ่ม `guestUrl` = `${origin}/remote#g=${โทเคนแขกรอบปัจจุบัน}` และ `qrSvg` (ถ้า `guestUrl` ยาวเกินที่ `qrSvg` รับได้ ให้ `qrSvg: null`)

- `admin`: `adminKey` ว่าง → 503 `admin_disabled` · หัว `Authorization` ไม่ตรง `adminKey` (เทียบแบบ `timingSafeEqual`) → 401 `bad_admin_key`
